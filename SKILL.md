# Fast material-shortage → finished-good impact

## Contract
- Read Anaplan model `PMGT - Inventory Planning V6.0` and the user-provided Excel BOM **read-only**. Do not change the model, import or order anything.
- Two-stage flow: (1) find material/location/week shortages; (2) only if asked, join those results to the BOM and calculate finished-good impact. Do not open/parse BOM for a stockouts-only question. On follow-up reuse *metadata and BOM structure* but re-read inventory if the user says it changed, refreshed, or asks to re-run. Never treat a previous answer's numerical results as current.
- Preserve explicit scope from conversation: Florida DC, Scenario 1, and 26 weeks if the user has specified them. If not specified, use all locations and the full forecast horizon and disclose that. Scenario selection is not interchangeable with native Versions; resolve the actual scenario dimension from the schema. If several scenarios exist and none was selected, ask which one rather than silently choose.
- If Anaplan cannot be read, stop and explain. If the BOM cannot be read for a finished-goods request, stop the finished-goods analysis and ask for the Excel sheet; a search excerpt or previous narrative is not a refreshed workbook. Do not claim complete coverage of a partial scan.

## 1. Discover once, not every week
1. Get bound model context; bind by cataloging models if needed, selecting the named model. Check model status if read fails. Locate `IEO200` using module catalog; get the exact Blueprint names/formats/dimensions of `Shortfall (U)` and, if available, forecast ending inventory and safety stock. Catalog relevant list names only when needed to resolve Florida or product codes. `sql_schema` using exactly the chosen module and line items: copy dimension column names verbatim. Do not assume location/product/time/scenario column names.
2. For relative time call `list_time_anchors`; if candidates conflict, ask which period to use. If they agree set the time anchor. Use `get_time_metadata` and the module's Time table / calendar to obtain periods **in model order**; derive 26 consecutive weekly member labels from the anchor without inventing dates. If no weeks can be read, ask for a valid horizon. Do not mistake the actual calendar date of reading for the model's current period. If period boundaries are available, note if historical.
3. Read the list member or use the exact known member `Florida DC` only after verification. Confirm scenario is `Scenario 1` in its actual dimension. If native Versions appears, pin exactly one explicit native version in **every** query. Reuse this discovered schema within the run; rediscover only if model structure changed.

## 2. Stockout scan: bounded and complete
- Prefer a single read with Florida and Scenario 1 fixed, and product + week as leaf dimensions **only when** it is small enough to page fully (use `read_cells` with pagination). Never take a first LIMIT page to mean no other shortages exist. Treat blank as unknown, not as zero unless the model says otherwise.
- For large product×week grids, use one bounded `sql_query` per week (or a proven-safe small range): pin Florida, Scenario 1, time to a single actual week, and native version if present; leave only product as leaf. Filter `Shortfall (U) < 0` since the user clarified negatives mean unmet demand. Use an explicit positive LIMIT and paginate/partition if results hit the cap. Use `COALESCE` only if blank should count as zero; negative comparison needs no coercion. Never use `!=`, and do not combine measure filtering with two free leaf dimensions. Read the projected inventory balance as well if available; flag balances < 0 and < safety stock when safety-stock data is available and comparable. A negative shortfall signals unmet demand, not a balance or remaining stock.
- Schedule independent week reads in parallel only within service limits; on rate-limit errors back off, reduce batch size and resume missing weeks instead of rerunning completed weeks. Record which weeks were actually scanned and distinguish incomplete scan from a true zero. The SQL included_objects map must contain exactly one module and be identical across schema/query. Query exact schema-generated names, not guessed aliases.
- Produce one row per material/location/first negative week, negative value with units, optionally worst week; preserve all other relevant weekly rows for BOM join. Group only after confirming page coverage. A stockout-only question ends here, with scope, forecast horizon, read date and caveats.

## 3. BOM join only on production-impact question
1. Read every row of the supplied Excel sheet, including finished good, parent, component, Anaplan code, level, base and selected/configured quantity, and UOM. If attachment is not accessible, request it; do not pretend an extracted PDF excerpt is the entire live workbook. Index BOM once by confirmed Anaplan component code, falling back to an explicitly verified exact ID/SKU mapping. Codes can repeat across finished goods; map **all** occurrences. Never join by a fuzzy description, family similarity, or part number that conflicts with code. List unmatched inventory products and BOM materials under data issues and exclude them from computed impact.
2. Explode multi-level parent→child paths, multiply required quantities along each path, sum paths to the same leaf material per finished good, and detect cycles. A level number alone is not a parent-child link: if the sheet doesn't establish parent relationship or selected frame/blade count, don't invent one. For example, don't presume a Synergy 480 blade is required for every Synergy 12000 Frame. Respect base quantity 0: optional GPU/storage options are **conditional** risks, not mandatory shortages absent a chosen configuration.
3. Match each flagged material to **every** finished good using it, preserving conflicts/shared materials and different configurations. For each finished good/location find the earliest at-risk week and report all simultaneous bottlenecks where appropriate. Maximum buildable units = min over *all required components* of floor(max(0, available component inventory for build)/units per finished good). If inventory, configured quantities, reserved/allocated stock or intended build quantity are absent, write `not determinable`; `Shortfall (U)` cannot substitute for available inventory. Unbuildable units require planned builds minus buildable units, bounded below by zero; don't turn a material gap directly into FG units. If a component's forecast inventory is negative, cap usable stock at zero for this arithmetic.
4. Severity relative to model anchor: Critical if first shortfall in weeks 1–4 or confirmed zero buildability; High weeks 5–8; Medium after week 8 or below safety stock only. Report a conditional severity for optional components rather than count them as confirmed mandatory FG risks. Count distinct FG risks by severity, not number of weekly material cells; order by severity then first week.

## 4. Advise, don't execute
- For each Critical and High FG, rank feasible candidate actions by time to resolve: verify uncommitted surplus at other locations and transit time before recommending transfer; inspect actual open PO and arrival before proposing expedite; assess new PO against confirmed supplier lead time; use only an explicitly approved substitute. If timing is infeasible, suggest prioritizing unaffected builds and flag likely delivery impact. If one material serves multiple finished goods, ask planner for build allocation priorities.
- Every *specific* recommendation must name material, required quantity, destination location and target week/date, and not assert availability or feasibility without evidence. If a material gap is fractional, ceil only for an investigation target in whole EA, explaining this is **not** an approved order or transfer quantity; do not sum carried-forward weekly shortfalls without model evidence. If lead times, donor surplus, PO or build demand are unknown, say what to verify and ask for missing inputs, rather than asserting an action is possible. Historical model weeks cannot be fixed by actions taken today.

## Output
First line: number of **confirmed** finished goods at risk by severity and most urgent issue. Then table sorted by severity/earliest period: severity | finished good | constraining material | location | first period at risk | material shortfall (or inventory vs safety stock) | finished-good units unbuildable. For stockouts-only request instead list all material/location/first-week risks and defer BOM mapping. Add ranked recommendations under each Critical/High FG; close with missing matches, optional items, missing inputs, incomplete scan, model anchor and exact weeks scanned, forecast horizon, and date data was read. If source can't be read stop, never reuse previous figures as fresh results.

## Quick regression checks
- Prompt: “I manage Florida; where are projected stockouts in the future?” → Scan Scenario 1 if context confirms; full horizon absent a user-defined horizon; return material/week results, no BOM access.
- Follow-up: “Which finished goods will be affected in production at Florida?” → Read Excel BOM; join confirmed codes; present all FGs per component; don't infer buildable units from shortfall.
- Prompt: “Refresh, check 26 weeks now” → Re-read Anaplan values for 26 model-anchored weeks; preserve prior context for location/scenario but discard prior numbers; report incomplete scan if throttled.
